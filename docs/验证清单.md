# dsh-forget-session v2 验证 / 排障清单

## 用法

### 遗忘会话（两段式确认）

1. 会话行「…」菜单 → 点 **「遗忘会话」**
2. 该行变成 **「再次点击确认遗忘」**（此时再点才真正执行）
3. 再点一次 → 行消失，会话与其磁盘数据被移除；顶部 Toast 汇报删除摘要
4. 之后 2 分钟内插件自动复查 ~5 次：复活文件（Windows 句柄残留 /
   teardown 迟到写入重建）会被自动补删，客户端列表会被自动重拉对齐

不想删就点别处关掉菜单即可，不会有任何副作用。

### 会话体检（一键清幽灵）

1. 任意会话行「…」菜单 → 点 **「会话体检（清扫空壳）」**
2. 该行变成 **「再次点击确认体检清扫」**
3. 再点一次 → Host 盘点全部磁盘会话目录（audit）+ 清扫空壳
   （sweepShells apply），Toast 汇报
   「体检完成：未记账磁盘会话 N 个，清扫空壳 M 个」

## 会话行为什么会真正消失（机制）

侧栏分组的官方算法：

```
accounted = 所有 workspace.sessionIds 的并集
未分组    = 客户端会话列表里的 id − accounted
```

官方让行消失的通道是服务端 `api-session/removed` 帧 → 客户端
`sessions.handleSessionRemoved(id)`。本插件的浏览器半在删除成功后直接调用
同一个官方方法，再调用 `sessions.refresh()` 重拉基线 —— 即使 Host 因活体
仍列出该会话，复查窗口内的 refresh + verify(apply) 也会把复活行再次摘掉。

## 「未分组」幽灵的三个来源（v2 全部根治）

1. **空壳会话**（v1 清扫 bug 已修复）：v1 的 `sweepShells` 用了未导入的
   `zlib`，对 zstd 日志恒抛 ReferenceError 被吞 → 空壳从未被清掉，重启后
   registry 重新收编进「未分组」。v2 修复后用**会话体检**一键清掉存量。
2. **Windows 活体删除竞态**（v2 复活守卫已修复）：会话打开过就有 write
   handle / 跨进程 lease，`rm` 报 EBUSY 静默失败 → 文件残留 → 重启后
   回到「未分组」。v2 删除后验证性复查 + 退避重试 + ~130s 复活守卫，
   句柄释放后或 teardown 迟到写入重建后都会自动补删。
3. **客户端列表复活**（v2 verify + refresh 已修复）：Host 的 session.list
   仍列出活体会话，客户端重连触发的 refreshList 会把已删行合并回来。
   v2 在 +4s / +20s 各复查一次并重拉官方列表。

## 重启后自检

- 菜单里能看到「遗忘会话」和「会话体检」 → 客户端半已加载
- 点第一次会变成「再次点击确认…」 → 交互链正常
- 点第二次后行消失、且**不出现**「未分组」 → 修复生效
- 删除后等 30 秒再刷新/重连 → 行不再回来（verify + 守卫生效）

## 若出现异常

错误**直接显示在菜单行上**（不静默）：

| 行上显示 | 含义 | 处理 |
|---|---|---|
| `遗忘失败：Host 服务未连接（restart DSH）` | 宿主半没加载 | 重启 DSH |
| `遗忘失败：workspaceRegistry service is unavailable` | workspace 插件未就绪 | 重启 DSH |
| `file still present after retries`（控制台警告） | Windows 句柄残留 | 无需处理 —— 复活守卫会在句柄释放后自动补删；或稍后跑一次「会话体检」 |

## 深度排查（audit 只读盘点）

任何怀疑残留时，开发者控制台执行：

```js
const svc = window.__DSH_BOOT__ && undefined; // 占位：见下
```

实际入口（Host 端语义）：`audit` 远端方法返回磁盘上**每个**会话目录的
`{ sessionId, accounted, archived, live, shellish, cwd, origin, bytes }`。
`accounted:false && live:false` 的条目就是幽灵候选；`shellish:true` 的
会被「会话体检」清扫。

## 恢复点

删除前会先走官方「停止并归档」通道再摘记账。即使中途失败，会话最坏情况
是**「已归档」**，可在侧栏「全部对话（显示已归档）」找回（此路径下磁盘
文件仍在）。

## 记忆完整性

灵枢记忆走 `session/event` 事件流、数据在 `~/.dsh/.dsh-memory`，
与会话日志/投影缓存文件不相交，遗忘会话不影响已沉淀的记忆。
