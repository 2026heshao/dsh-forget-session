# dsh-forget-session 验证 / 排障清单

## 用法（两段式确认）

1. 会话行「…」菜单 → 点 **「遗忘会话」**
2. 该行变成 **「再次点击确认遗忘」**（此时再点才真正执行）
3. 再点一次 → 行消失，会话与其磁盘数据被移除

不想删就点别处关掉菜单即可，不会有任何副作用。

## 会话行为什么会真正消失（机制）

侧栏分组的官方算法是：

```
accounted = 所有 workspace.sessionIds 的并集
未分组    = 客户端会话列表里的 id − accounted
```

所以**只摘 Host 记账是不够的** —— 客户端会话列表里的 id 会掉进「未分组」。
官方让行消失的通道是服务端 `api-session/removed` 帧 → 客户端
`sessions.handleSessionRemoved(id)`。

本插件的浏览器半在删除成功后**直接调用同一个官方方法**
（`ctx.get("sessions").handleSessionRemoved(id)`），等价于补发那一帧，
因此行会立即消失、不再产生「未分组」残影。

## 重启后自检

- 菜单里能看到「遗忘会话」 → 客户端半已加载
- 点第一次会变成「再次点击确认遗忘」 → 交互链正常
- 点第二次后行消失、且**不出现**「未分组」 → 修复生效

## 若出现异常

新版把错误**直接显示在菜单行上**（不再静默）：

| 行上显示 | 含义 | 处理 |
|---|---|---|
| `遗忘失败：Host 服务未连接（restart DSH）` | 宿主半没加载 | 重启 DSH |
| `遗忘失败：workspaceRegistry service is unavailable` | workspace 插件未就绪 | 重启 DSH |
| 其它错误文本 | Host 抛出的具体原因 | 把原文发给助手 |

菜单里**完全没有**这一行时：插件未加载（多半是安装目录里的副本是旧代码，见下）。

## 历史残影处理

在本次修复**之前**删掉的会话，其行可能仍留在当时那个 DSH 进程的「未分组」里
（磁盘文件其实已经删掉了）。这类残影**重启 DSH 即消失** —— 客户端会按磁盘
真实状态重建会话列表。修复后的删除不再产生残影。

## 部署注意（重要）

本插件在 profile 里以 **junction** 直连源码目录：

```
C:\Users\LENOVO\.dsh\profiles\desktop\node_modules\dsh-forget-session
   → D:\桌面\AI Port\DSH plugins\dsh-forget-session
```

所以**改源码后只需重启 DSH**，不需要重跑 `pnpm install`。

⚠️ 曾经的坑：`pnpm install` 对 `file:` 目录依赖**不会重新复制**已改动的文件，
导致「改了源码、装了、但 DSH 跑的还是旧代码」。改用 junction 后此坑消失。
若某次 `pnpm install` 把 junction 换成了真实目录副本，重新建立 junction 即可：

```powershell
cmd /c rmdir "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-forget-session"
New-Item -ItemType Junction `
  -Path "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-forget-session" `
  -Target "D:\桌面\AI Port\DSH plugins\dsh-forget-session"
```

## 恢复点

删除前会先走官方「停止并归档」通道再摘记账。即使中途失败，会话最坏情况是
**「已归档」**，可在侧栏「全部对话（显示已归档）」找回（此路径下磁盘文件仍在）。

## 记忆完整性

灵枢记忆走 `session/event` 事件流、数据在 `~/.dsh/.dsh-memory`，
与会话日志/投影缓存文件不相交，遗忘会话不影响已沉淀的记忆。
